## Task 1 — bind citation chips to their sentence

Problem seen in the 0.2 screenshots: in APA style the chips are long enough to
wrap onto their own line, so a chip can start a line and read as though it
introduces the sentence that follows rather than closing the one before it.
LitLens promises that every claim is checkable, so this binding has to be
unambiguous in all six citation styles.

- Wrap each answer sentence in a span carrying a stable `data-sentence-id`, and
  give each citation chip a `data-cites` attribute naming the sentence it
  supports. Keep this structure even though the content is sample data now — the
  real citation mapping in slice 2.3 will use it.
- A chip must never begin a line. Bind each chip to the last word of its sentence
  so the two wrap together.
- On hover or keyboard focus of a chip, mark the sentence it supports with a
  subtle background tint. Do not use the highlighter yellow for this: yellow
  stays reserved for evidence in the source panel. Clicking a chip keeps its
  current behaviour of focusing the source passage.
- Each chip is a real button with an accessible name, e.g.
  "Source: Calloway et al., 2023, page 4".
- Verify at 390 and 1280, in all six styles, that no chip begins a line.

## Task 2 — remove the duplicate Library heading on mobile

The mobile drawer header and the panel inside it both read "Library". Keep one

## Task 3 — live demo loop (decision D19)

LitLens gets a live animated background, but only on screens with nothing to
read. The library, answer column and source panel stay still. Build one
component, used in three places.

The animation is the real interaction replaying itself:

1. A sheet settles onto the desk.
2. A question types into the ask box.
3. The answer appears one sentence at a time.
4. A citation chip appears after a sentence.
5. The chip activates, and the source passage highlights in highlighter yellow.
6. Hold, fade, restart. Aim for a 12–15 second loop.

Placement:
- **Home:** the full loop, behind the hero content. Headline and button text must
  meet WCAG AA contrast at every frame of the loop, not just the first.
- **Sign-in:** a quieter variant — slower, lower contrast, and it plays once
  rather than looping, so it doesn't compete with the sign-in action.
- **Library empty state:** a compact variant.

Constraints:
- Build it from the real design-system components and tokens, on hardcoded sample
  data in one self-contained component. No video, no GIF, no canvas or particle
  library. It must not be able to drift from the design system, and it must be
  removable without touching the shell.
- Drive it with Motion from a single timeline. Animate transform and opacity
  only, never layout properties.
- `prefers-reduced-motion: reduce` renders the end state statically, with no
  motion at all.
- Pause via IntersectionObserver when off-screen, and on `document.hidden`.
- Reserve its space so there is no layout shift. The first paint shows the end
  state.
- Home must keep a mobile Lighthouse performance score of 90 or above, measured
  on a production build. Report the score.
- Works in light and dark. Check that the highlighter yellow still reads as a
  highlight on the ink-navy desk rather than glaring.
- D17's avoid list still applies: no decorative gradient fills, no shadow-card
  grids, no all-caps labels, no eyebrows, no arrows on buttons.

If this task is not working well within one session, stop and ship a static still
of the loop's end state instead, and say so in your report.

## Task 4 — make references degrade gracefully (decision D20)

The citation style switcher and References block stay. Slice 1.2 has not yet
shown what reference metadata Docling actually returns, so the References block
must never invent anything.

- When a field is missing (journal, volume, issue, page range, publisher), render
  what is known and mark the gap visibly. Never substitute a plausible value.
- A reference missing enough fields to be unusable in the selected style says so
  plainly rather than rendering a malformed entry.
- Add unit tests covering, for each of the six styles, a complete reference and a
  reference with missing volume, issue and page range.
- "Copy references" copies exactly what is displayed, gaps included.

## Decisions to record as ADRs

- **D19 — motion scope.** A live animated background on home, sign-in and empty
  states only, as a demo loop of the real interaction. Reading surfaces stay
  still, because motion behind long-form text fights the task the app exists for.
- **D20 — citation styles stay in the app shell.** This expands R5. Conditional on
  references degrading gracefully, revisited once slice 1.2 shows what the parser
  extracts.

Slice 0.3 approved. Answers to your five points, then one small follow-up slice.

**1. httpx2 — yes, declare it at the root.** I checked it independently and it's
legitimate: Pydantic Services took over stewardship of httpx under that name in
May 2026, BSD-3, same API, still authored by Tom Christie. Two caveats worth a
note in the repo: a high-severity vulnerability is reported against 2.0.0
specifically, so keep the pin current (2.16.2 at time of writing); and httpx2
silences anything that instruments httpx — OpenTelemetry's
HTTPXClientInstrumentor, respx, pytest-httpx, vcrpy — unless
`httpx2.alias_httpx()` is called before anything imports httpx. That will matter
when Langfuse is wired up in 2.2 and 4.2, so put it in the gotchas.

**2 and 4 — one function, decision D22.** They're the same problem. Build a
single `security definer` function, called with the user's own JWT, that:
  - increments `usage_daily` for `auth.uid()` (working for anonymous sessions
    too, per D21),
  - sets `last_active_at = now()` itself for signed-in users,
  - returns the remaining allowance so the UI can show it.

Then remove `last_active_at` from the columns a profile update may set, so a
user can't push it into the future and dodge the D9 clean-up. The API must
never hold the service-role key — the Modal worker stays the only service-role
component, and this function is the single narrow exception.

**3 — don't persist anonymous answers, decision D23.** Hold them in the client
for the session. Refreshing loses them, which is fine for a demo. Langfuse keeps
the traces we actually need. This leaves anonymous sessions with no write path
to the database at all, which is a cleaner property than the feature is worth.

**5 — agreed.** A 0–100 field is right, and your reasoning is right: chunking and
embedding aren't measured in pages and the page count is unknown until the
parser opens the file.

## Slice 0.3b — the privileged write path

Implement D22 now, while the schema is fresh, rather than deferring it to 2.7.
Point 4 is a live hole today.

- The function, with a narrow signature. It must be impossible to use it to
  increment anyone else's counters — not by passing a user id, not by any
  argument. It reads `auth.uid()` and nothing else.
- `search_path = ''` and schema-qualified references throughout, as you did for
  the other functions.
- Revoke the profile update's ability to set `last_active_at`.
- Tests, in the same style as the 0.3 suite: A cannot inflate B's usage; an
  anonymous session is metered and gets its allowance back; a user cannot set
  `last_active_at` at all, directly or through the function; the function is
  callable with a user JWT and not with no session.
- Mutation-test it the way you did the policies. If you can't break it, say what
  you tried.
- ADR for D22, and one for D23.

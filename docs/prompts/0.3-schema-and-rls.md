## Task 3 — RLS policies

- RLS enabled on all eleven tables. No table without it.
- Ownership flows through `collections.owner_id = auth.uid()`.
- **Anonymous demo sessions:** Supabase anonymous sign-ins arrive as the
  `authenticated` role, not `anon`, so distinguish them with the `is_anonymous`
  JWT claim rather than the database role. An anonymous session gets SELECT on
  the demo collection's rows and on `demo_answers`, and nothing else anywhere.
  No INSERT, UPDATE or DELETE on any table.
- `eval_runs` is readable by everyone — the public eval page (R14) uses it.
- `usage_daily` is readable by its own user; only the service role writes it.
- **`papers` is the exception.** Enable RLS on it and write no policy, so it is
  deny-all. Add a comment in the migration saying the policy is written by hand
  in this slice and pointing at the tests. Leave it that way.

## Task 5 — tests

This is the part that matters most. The tests must prove isolation, not describe
it.

- Two real signed-in users, A and B, plus one anonymous session. Real JWTs
  through the anon public key.
- **Guard:** the test setup fails loudly if a service-role key is present in the
  environment. A test suite that silently runs as service role proves nothing.
- For every table: A cannot SELECT, UPDATE or DELETE B's rows, and gets zero
  rows rather than an error where that is the expected behaviour. A can reach its
  own rows.
- Anonymous: can read the demo collection and `demo_answers`; cannot read A's
  rows; cannot write anywhere.
- Storage: A cannot read B's folder.
- **`papers` tests, written now:**
  - Isolation tests (B cannot reach A's papers, anonymous cannot reach them)
    must pass immediately, because deny-all satisfies them.
  - Owner-access tests (A can select, insert and update its own papers) are
    marked `@pytest.mark.xfail(strict=True)` with a reason naming slice 0.3 and
    Likith. They fail today, so CI stays green; when the policy is written they
    pass, and strict mode turns that into a failure until the marker is removed.
- Add a CI job that starts Supabase and runs these tests. Keep it separate from
  the fast lint and typecheck jobs. If it pushes CI past about three minutes,
  move it to its own workflow and say so in your report.

## ADR

One ADR for this slice: RLS as the tenancy boundary, the API querying with the
user's JWT, and the worker's service-role key as the single privileged path.
Record that anonymous demo sessions are separated by the `is_anonymous` claim.

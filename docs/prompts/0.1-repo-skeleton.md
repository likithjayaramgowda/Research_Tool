I'm building LitLens, my portfolio project, and you'll write the code while I learn from it. I'm a data engineer (strong in Python and SQL, newer to web apps). Explain what you do and why in plain language as you go.

## About LitLens
A RAG web app for research students. They sign in with Google, upload up to 30 papers (50 MB) to a private workspace, and ask questions answered only from those papers, with a citation on every sentence. It also builds "paper cards", finds research gaps (including a "Gap Check" of the student's own idea), and checks each paper's relevance to their topic. Recruiters can try a demo without signing in. It's a portfolio prototype, not a product.

## Fixed decisions (ask me before changing any of these)
- Free tiers only, and no payment card on any service.
- Web: Next.js (App Router, TypeScript strict), Tailwind, shadcn/ui, Motion. Hosted on Vercel Hobby.
- API: Python FastAPI on Vercel's Python runtime, under /api/v1.
- Data: Supabase: Auth, Postgres with pgvector and full-text search, RLS, Storage, Realtime, Queues (pgmq), pg_cron, and an Edge Function `embed` using the built-in gte-small model.
- Worker: Python on Modal, for uploads and long jobs only. Docling is used only here.
- A shared Python package `core`, used by both the API and the worker. Light dependencies only.
- LLM: Groq, through a small provider-agnostic client we write ourselves.
- Public GitHub repo, MIT licence, no AGPL dependencies (so no PyMuPDF). Never commit secrets.

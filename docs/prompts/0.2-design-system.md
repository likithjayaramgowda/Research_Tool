## Design direction (follow it, and ask me before changing it)
LitLens is a reading tool for research students. Its promise is that every answer can be checked against its source. The look is a light table for papers: white sheets on a cool desk, ink-coloured text, and one highlighter yellow that only ever means "evidence".

Palette for light mode. Derive a dark mode that keeps the same meanings on a deep ink-navy desk, never pure black.
- Desk #E9EDF0: app background
- Sheet #FFFFFF: reading surfaces (answers, passages, paper cards)
- Ink #18233A: text, primary buttons, focus rings
- Graphite #5B6675: secondary text, borders, icons
- Highlighter #FFE14D: citations and highlighted passages only. Nothing else is ever yellow.
- Alert #B42318: errors only

Type:
- Literata (variable, via next/font): headings, answers, passages and paper titles. Body 17px, line-height 1.6, max 70 characters per line.
- Atkinson Hyperlegible Next (via next/font; use Atkinson Hyperlegible if Next isn't available): UI, buttons, labels and metadata. 15px base.
- Scale of about 1.25: 13, 15, 17, 21, 26, 33, 41, 52. Weights 400 and 600 only.

Signature interaction, "the lens": choosing a citation chip in an answer brings its source into focus. The source sheet scrolls to the passage, the passage is highlighted in yellow, and everything else dims (keep dimmed text at 3:1 contrast or more). Use Motion, under 200 ms, and switch instantly when prefers-reduced-motion is set. Tab and Enter do the same, and Escape clears it.

Rules:
- Left-aligned text and generous whitespace. Show hierarchy with type and spacing, not boxes.
- Never use gradients, grids of shadowed cards, one radius on everything (use 6px for sheets, pills only for citation chips), all-caps labels, small labels above headings, arrows added to button text, monospace for small labels, or text joined with dots.
- Motion only responds to an action. The one exception is the landing hero, which plays once.
- WCAG 2.2 AA contrast, a visible focus state on everything, and layouts that work at 360px wide.
- Empty and error states get short placeholders marked TODO(copy). I'll write the final words.

## Build in this order
1. Tokens: theme tokens as CSS variables for both modes (keep the Tailwind version 0.1 installed), fonts via next/font, and a light/dark toggle that starts from the system setting.
2. Components: shadcn/ui as the base, restyled to these tokens (Button, Input, Textarea, Tabs, Dialog, Sheet, Tooltip, DropdownMenu, Sonner toasts, Skeleton, Progress, ScrollArea). LitLens components:
   - CitationChip
   - SourcePassage
   - Answer: sentences with chips
   - PaperRow: with a status of Uploading, Reading, Ready or Failed
   - PaperCard: the title plus Question, Method, Data, Findings and Limitations
   - UploadDropzone: UI only
   - EmptyState
3. A /design page showing every token and component in both modes.
   Stop here. Commit, save screenshots of /design in both modes to docs/screenshots/, and wait for my OK before building pages.
4. The landing page (/):
   - Hero headline: "Ask your papers. See exactly where each answer comes from." Supporting line: "Upload up to 30 papers. LitLens answers only from them, cites the page for every sentence, and tells you when the answer isn't there."
   - Beside the hero, a small working example of the lens: a question, a two-sentence answer with chips, and the source passage that comes into focus when a chip is chosen. It plays once on load, then waits for the visitor.
   - Two buttons: "Try the demo" and "Sign in with Google". There's no auth yet, so both go to placeholder routes.

   - On mobile, the library becomes a drawer and the source becomes a bottom sheet.

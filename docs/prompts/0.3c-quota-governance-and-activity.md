Slice 0.3c — quota governance and activity. Builds on `record_usage`.

Read `docs/requirements-and-decisions.md` first; I'll hand you an updated copy
with D24 and D25 in it. End it with a trailing newline this time, and drop the
pre-commit exclusion — a permanent carve-out isn't worth byte-for-byte fidelity
on a doc.

## 1 — Lower the starting allowances (D24a)

Signed-in: 10 questions, 1 Gap Check per day. Anonymous: 3 questions, no Gap
Checks. The old numbers were about half of one Groq model's entire daily budget
for a single user.

## 2 — Add a global daily ceiling (D24b, D24c)

Per-user caps don't protect a shared quota: fifty users under a modest allowance
still exhaust it. The three Groq models give ~600K tokens a day across everyone
combined, so about 120–150 questions total.

- A global counter per UTC day, starting at **100 weighted questions**, with a
  Gap Check weighing **6** (≈30K tokens against ≈5K).
- `record_usage` checks and increments it in the **same single statement** as the
  per-user counter, for the same reason the per-user check is atomic.
- The ceiling lives in `private` alongside `daily_allowance`, so it's tunable
  without a code change.

**When the ceiling is hit, the demo must still work.** Precomputed demo answers
cost nothing, so they keep being served; only live questions are refused. Return
a **distinguishable** result for the two refusals — personal allowance spent
versus global ceiling reached — because the UI has to say different things.
Leave the wording as `TODO(copy)`; Likith writes microcopy.

## 3 — Activity is any session (D25)

Add a third kind that counts nothing, costs no allowance, and only stamps
`last_active_at`. The web app calls it once per session on load. A signed-in
user who reads their library without asking anything must not be deleted at 30
days under D9.

## 4 — Let users see what's left (D25)

Don't add a second `security definer` function — that would trip your own pgTAP
guard, correctly. Instead widen the existing `usage_daily` select policy to
`user_id = auth.uid()`, so anonymous sessions can read their own row too. Writes
stay function-only.

## 5 — Tests and mutation testing

Same standard as 0.3b. At minimum: the global ceiling refuses an eleventh user
once reached even when that user has personal allowance left; a refused call
increments nothing, globally or personally; Gap Checks move the global counter by
6; the activity kind stamps `last_active_at` without touching any counter and
without spending allowance; anonymous sessions can read their own usage row and
still not write it; the two refusal kinds are distinguishable.

Mutation-test it, including: global ceiling never enforced; global counter
incremented outside the atomic statement; activity kind silently spending
allowance; the usage read policy widened past `auth.uid()`.

## 6 — ADR

ADR for D24 and D25. Record in the D24 ADR that **evals run on Gemini, not
Groq** (D5 permits it for the author's own work on public papers, and the demo
set is CC BY per D14). The nightly 60-question run is ~300K tokens, half the
daily Groq budget, and each PR's 15-question subset is ~75K — on a busy day
evals alone could starve the live demo. The eval harness in 2.5 and the CI eval
jobs must target the Gemini adapter explicitly rather than inheriting the
default.
